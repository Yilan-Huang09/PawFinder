# PawFinder 答辩提纲

## 8 分钟结构

1. 30 秒：问题与一句话方案。
2. 60 秒：三类用户和业务闭环。
3. 90 秒：E-R 图、11 张表和第三范式。
4. 90 秒：函数、触发器、视图与寻回事务。
5. 2 分钟：发布、匹配、认领、寻回现场演示。
6. 60 秒：测试与异常降级。
7. 30 秒：创新点和总结。

技术架构页建议展示 `Nginx/Vue → Flask/Gunicorn → MySQL 8`，并注明既支持 Docker Compose 一键部署，也保留 Windows 本地启动方式。

## 常见问题

- 目击为何不直接绑定事件：避免误判，并让一条线索参与多个候选计算。
- 如何防止重复认领：条件更新只允许 `AVAILABLE` 成功一次。
- 为何用存储过程：寻回涉及多表状态，需要集中证明原子性。
- 没有地图或 AI 密钥怎么办：无高德密钥时显示 OpenStreetMap，外部地图失败时保留坐标列表；AI 使用本地模板保证运行。
